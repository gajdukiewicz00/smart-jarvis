## 🔄 ПРОЦЕСС РАБОТЫ

### 1. Планирование итерации
- [ ] Прочитать текущую итерацию в [tasklist.md](./tasklist.md)
- [ ] Изучить требования и критерии готовности
- [ ] Предложить архитектурное решение с примерами кода
- [ ] **Дождаться согласования** от пользователя

### 2. Реализация
- [ ] Создать/изменить файлы согласно согласованному решению
- [ ] Следовать правилам из [conventions.md](../conventions.md)
- [ ] Добавить тесты для новой функциональности
- [ ] Проверить работоспособность

### 3. Тестирование
- [ ] Выполнить команды тестирования из итерации
- [ ] Проверить все критерии готовности
- [ ] Исправить найденные проблемы
- [ ] **Дождаться подтверждения** от пользователя

### 4. Завершение
- [ ] Обновить прогресс в [tasklist.md](./tasklist.md)
- [ ] Отметить выполненные задачи чекбоксами
- [ ] Сделать коммит в репозиторий
- [ ] **Согласовать переход** к следующей итерации

## 🎯 ПРАВИЛА ВЫПОЛНЕНИЯ

### Обязательные действия:
1. **Всегда согласовывать** архитектурные решения
2. **Всегда ждать подтверждения** перед переходом
3. **Всегда обновлять** прогресс в тасклисте
4. **Всегда коммитить** изменения
5. **Всегда тестировать** функциональность

### Запрещено:
- ❌ Создавать монолитные решения — только микросервисы
- ❌ Переходить к следующей итерации без согласования
- ❌ Пропускать тестирование
- ❌ Не обновлять прогресс
- ❌ Делать изменения без согласования

### Приоритеты:
1. **ПОЛНАЯ МИКРОСЕРВИСНОСТЬ** — каждая функция = отдельный сервис
2. **Качество** — код должен быть чистым и тестируемым
3. **Функциональность** — все должно работать
4. **Производительность** — латентность < 2 сек
5. **Безопасность** — валидация и allowlist
6. **Документация** — обновление README и комментариев

## 🔧 КОМАНДЫ ДЛЯ РАБОТЫ

### Разработка:
```bash
# Поднять инфраструктуру
make up

# Проверить статус
make status

# Посмотреть логи
make logs

# Запустить тесты
make test

# Остановить все
make down
```

### Git:
```bash
# Добавить изменения
git add .

# Сделать коммит
git commit -m "feat: implement iteration X"

# Отправить в репозиторий
git push
```

## 📝 ШАБЛОН КОММИТА

### Conventional Commits:
```
feat: add voice gateway with WebSocket support
fix: resolve memory leak in todo service
docs: update API documentation
test: add integration tests for todo service
refactor: extract todo validation logic
```

### Структура:
- **feat:** новая функциональность
- **fix:** исправление багов
- **docs:** документация
- **test:** тесты
- **refactor:** рефакторинг
- **chore:** технические задачи

## 🚨 ОБРАБОТКА ОШИБОК

### При ошибках:
1. **Остановить** выполнение
2. **Проанализировать** проблему
3. **Предложить** решение
4. **Согласовать** с пользователем
5. **Реализовать** исправление
6. **Протестировать** снова

### Типичные проблемы:
- **Docker не запускается** → проверить порты и ресурсы
- **Kafka не работает** → проверить Zookeeper
- **Сервисы не видят друг друга** → проверить сеть Docker
- **Тесты падают** → проверить зависимости
